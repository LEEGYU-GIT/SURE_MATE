# M5 Sure-Mate 바·펼침 창·선택 글 위키 카드 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 화면 가장자리의 Sure-Mate 바(가장자리 띠·떠 있는 캡슐·끄기)에서 팔레트를 열지 않고 고정 프롬프트 실행·가명 처리 모드 변경·용어 사전 열기를 하고, `Ctrl+Alt+W`로 선택한 글의 용어를 바 옆 위키 카드로 확인한다(F9 §14-1, §9 위키 카드). 바와 펼침 창은 포커스를 빼앗지 않고 전체 화면 앱 앞에서는 숨는다.

**Architecture:** 판단은 모두 순수 모듈에 둔다. 항목·크기·위치(DIP)는 `shared/bar/`, 전체 화면·맨 앞 유지·자동 숨김·바 컨트롤러는 `main/bar/`, 펼침 창 배치·타이머는 `main/flyout/`에 두고, 창·화면·시계를 주입받아 가짜 시계로 시험한다(`capture-flow.ts`와 같은 방식). Electron 창 두 개(`bar-window.ts`·`flyout-window.ts`)와 Win32 호출(`SHQueryUserNotificationState`·`SetWindowPos`)은 얇은 연결부만 둔다. 화면은 같은 renderer 번들의 `#/bar`·`#/flyout` 경로로 그리고, 리눅스에서는 설치 파일에 포함되지 않는 개발용 미리 보기(`preview.html` + 가짜 `window.sureMate`)를 headless Chrome으로 캡처해 시안과 비교한다.

**Tech Stack:** Electron 45.2.3, React 19, TypeScript, Tailwind v4, Vite 8, Vitest, koffi 3. 새 의존성 없음.

**Spec:** `docs/superpowers/specs/2026-11-05-sure-mate-design.md` (§5 창, §9 선택 텍스트 위키 카드, §10 가져오기, §14 바 설정 항목, §14-1 F9 Sure-Mate 바, §14-4 디자인 시스템, §16, §19) · 확정 시안 `docs/design/mallang-mate.html` "바 두 모양 위의 말랑 메이트" · `docs/decisions.md`

- 말랑 메이트 창(M6): 바의 펫 단추는 `settings.pet.visible`만 바꾼다. M6 "펫 창" 작업이 이 값을 읽고, 바 런타임의 `raise()` 순서 끝과 전체 화면 숨김(`onFullscreen`)에 펫 창을 추가한다.
- 워크스페이스 저장·불러오기(M7): 바의 워크스페이스 펼침은 빈 목록과 "준비 중" 안내만 표시한다. M7 워크스페이스 작업이 `workspace-menu`의 `workspaces`·`canSave`와 실행·저장 동작을 채운다.
- 설정 화면(11/15): 그때까지 바의 설정 단추와 바 메뉴 "설정 열기"는 `settings.json`을 기본 프로그램으로 연다. 설정 화면 작업이 `openSettings`를 설정 창 열기로 교체한다.

## Global Constraints

- 리눅스 서버: 명령은 `desktop/`에서 Node 22로 실행한다. 기본 `node`는 v12이므로 먼저 `export PATH="$(git rev-parse --show-toplevel)/../../tools/node22/bin:$PATH"`를 실행하고 `node --version`(22 이상)을 확인한다. 리눅스에서 가능한 검증은 `npx vitest run <파일>`, `npm test`, `npm run typecheck`, `npx electron-vite build`, 미리 보기 캡처뿐이다. Win32·Electron 창 동작은 Task 13(Windows)에서만 확인한다.
- 모든 BrowserWindow: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, `spellcheck: false`.
- 바 창(§14-1): `frame:false, transparent:true, focusable:false, skipTaskbar:true, resizable:false, type:'toolbar'`, `alwaysOnTop: true` 수준 `'screen-saver'`, `showInactive()`로 표시. 펼침 창(§9): `show:false, frame:false, transparent:true, focusable:false, type:'toolbar', alwaysOnTop:true` + `showInactive()`, 내용이 바뀌면 맨 앞으로 올린다.
- 크기(§14-1, DIP): 가장자리 띠 너비 56·안쪽 모서리 8, 떠 있는 캡슐 너비 44·가장자리에서 12·완전히 둥글게·마우스를 올린 아이콘 1.15배. 기본은 가장자리 띠·오른쪽·주 모니터. 높이는 항목 수에 맞추고 화면 전체를 덮지 않는다.
- 시간(§14-1·§9·§14-4): 이름표 400ms, 맨 앞 유지는 보일 때만 2초마다, 전체 화면 확인은 1초마다(`SHQueryUserNotificationState`가 2·3·4면 숨김), 자동 숨김 손잡이 6 DIP·손잡이에 300ms 올리면 나옴, 위키 카드 자동 숨김 8초(마우스를 올리면 유지), 움직임은 마우스 올림 120ms·펼침 200ms ease-out·바 들어가고 나오기 300ms.
- 펼침 창: 바 안쪽(오른쪽 바면 왼쪽)으로 8 DIP. 클릭만 받고 키보드 입력은 받지 않는다. 위키 카드 기본 너비 360 DIP.
- 색·글자·모양은 §14-4 토큰만 사용한다(`--surface-bar` 바, `--surface-flyout` 펼침 창·이름표, 그림자는 펼침 창에만 `--shadow-flyout`). 바·펼침 창은 CSS 반투명 단색이고 아크릴·`backdrop-filter`를 사용하지 않는다. 가명 처리 상태는 색만으로 알리지 않는다.
- 하루에 수십 번 누르는 바: 누르기에는 움직임을 두지 않고, 팔레트 열기·닫기에도 움직임을 추가하지 않는다(`emil-design-eng`의 잦은 동작 규칙). 움직임 값은 §14-4만 사용한다.
- 포커스: 바·펼침 창을 눌러도 원래 창의 포커스와 선택이 바뀌지 않는다. 전역 키보드·마우스 훅을 사용하지 않고 조회(`SHQueryUserNotificationState`, `GetAsyncKeyState`, `screen.getCursorScreenPoint`)만 한다.
- Win32는 `win32()`로만 호출한다. 바는 `nativeStatus()`가 실패해도 표시·동작한다(전체 화면 숨김과 바깥 클릭 닫기만 빠진다). 좌표는 모두 DIP로 계산하고, 물리 픽셀 변환이 필요하면 `coords.ts`만 사용한다.
- 로그: 선택한 글·클립보드·프롬프트·용어·설명 내용을 남기지 않는다(길이·id·건수·사각형만). 오류는 `errorText()`. 2초마다 맨 앞 올리기처럼 반복되는 일은 기록하지 않는다.
- 설정 저장은 `updateSettings`(파일을 다시 읽고 바꿀 값만 고친 뒤 원자적 저장)로 한다.
- 앱은 네트워크 요청을 보내지 않는다. 아이콘은 Lucide(ISC) SVG 경로를 `design/icons.tsx`에 복사한다(필요하면 lucide.dev나 저장소 밖 임시 폴더에 받은 `lucide-static`에서 복사, 의존성 추가 없음).
- 커밋 메시지는 `feat: …`(한국어), 실명 없음. 데모·시험 데이터 이름은 가상(가상자동차, XY방산)만 사용한다.

## Review Focus

1. **모니터 구성 변경**: 선택한 모니터를 분리하거나, 노트북을 도킹·해제하거나, 실행 중 배율을 바꾸면 바가 주 모니터(또는 선택한 모니터)에 정상 크기로 다시 놓이고 화면 밖으로 나가지 않으며, 모니터별 세로 위치가 복원된다. 작업 표시줄이 왼쪽·위쪽이어도 작업 영역 안에 놓인다. → Task 3(음수 좌표·작업 영역 시작점), Task 5(모니터 사라짐 → 주 모니터, 크기 어긋남 → 다시 맞추기), Task 7(카드 다시 놓기) 테스트.
2. **작은 화면**: 1280×720·125%(작업 영역 높이 약 538 DIP)에 고정 프롬프트 5개면 바가 화면을 넘지 않도록 뒤쪽 프롬프트부터 빠지고, 구분선이 연속되거나 끝에 남지 않는다. → Task 3 테스트.
3. **바쁠 때 누르기**: 고정 프롬프트를 빠르게 두 번 누르거나, 가져오는 중에 다시 누르거나, 팔레트가 열린 채 누르면 한 번만 실행된다. 팔레트가 열려 있으면 먼저 숨기고 원래 창으로 돌아가 가져온다(팔레트에 Ctrl+C를 보내지 않음). → Task 9·10 테스트.
4. **위키 카드의 큰 글·빈 글**: 20만 자를 선택해도 멈추지 않고(앞 2만 자만 찾음), 공백·줄바꿈만 선택했으면 "선택한 글 없음"으로 안내하며 클립보드 찾기를 제안하고, 터미널에서는 그 이유를 알린다. → Task 12 테스트.
5. **Win32 차단**: 보안 프로그램이 koffi를 막아도 앱 시작과 바 표시가 막히지 않고, 전체 화면 확인은 세 번 연속 실패하면 멈추고 한 번만 기록하며, 메뉴는 커서를 1.5초 밖에 두면 닫힌다. → Task 4·7 테스트, Task 13의 t12 갱신.
